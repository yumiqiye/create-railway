# 铁路检票 / 票务需求清单落地状态

> 本文件按手写笔记与整理后的需求清单逐条记录：已落地、部分落地、待实现和需要确认的点。
> 进度编号沿用清单：`BUG #x`、`改进项 #x`。

## 一、本轮已完成

### 模组侧
- **BUG #1 插卡开窗**：售票机第一次插入身份证只完成识别并提示“再次右键打开窗口”；第二次右键才打开售票机。
- **BUG #2 取票方式**：车票 / 报销凭证 / 行程单打印后，会把售票机内保存的身份证连同票据一起取回；机器内无卡时才同步背包身份证。
- 模组 `compileJava` 已通过。

### 网页后端
- 新增乘车人黑名单数据分桶：`highspeed`（高铁）、`metro`（地铁）。
- 新增黑名单管理接口：
  - `GET /railway/admin/blacklist?mode=highspeed|metro`
  - `POST /railway/admin/blacklist`
  - `DELETE /railway/admin/blacklist/:id?mode=highspeed|metro`
- 高铁下单时会拦截黑名单中的姓名 / 证件号，禁止购票。
- 新增购票机台账接口：
  - `GET /railway/admin/tvms`
  - `POST /railway/admin/tvms`
  - `PUT /railway/admin/tvms/:id`
  - `DELETE /railway/admin/tvms/:id`
- 系统设置补充：补票费率、快开车提示分钟数、闸机屏幕开关、版本阶段标识、地铁模式开关。
- 品牌下发信息补充上述设置，供模组 / 售票机读取。

### 后台前端 API 类型
- `web/admin/src/api/ticket/index.ts` 已补充黑名单、购票机台账、扩展设置字段的类型与请求方法。

## 四、建议下一轮优先级

1. **先补可验证 BUG**：引导屏缩放、Create 时刻表导入、多车次翻页复测、开检时间复测。
2. **再接设备闭环**：闸机编号绑定、网页配置下发、模组拉取配置。
3. **再做游戏内交互**：平板 / 电视、车载屏、车钥匙、调度对话。
4. **最后做地铁模式**：储值卡、站内到达预报、`/metro` 命令和地铁黑名单联动。

## 五、需要用户确认的点

- BUG #3 票价异常：请给出车次、出发站、到达站、席别、实际价格和预期价格。
- 大屏缩放期望：是按单块屏幕缩放，还是按整条拼屏缩放？缩放系数由谁在游戏内调整。
- 地铁模式是否需要独立端口 / 独立数据库，还是与高铁票务共用当前 Node 后端。
